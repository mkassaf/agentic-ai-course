Before your first call

A notebook and a little Python.

Use the same setup in each lab. You do not need a GPU or an agent framework.

{ }
01 / Bring the basics

Know your Python building blocks

Functions, lists, dictionaries, JSON, loops, and simple assertions. Know how to run a notebook cell and read an exception.

02 / Open a notebook

Run it in Google Colab

Open a lab with its Colab button. Until the repository is configured, download the notebook and use File → Upload notebook in Colab. Choose a CPU runtime.

03 / Choose a run mode

Practice, then call a real model

Run the scripted examples first. Start with MODE="practice". For live work, the initial settings use BASE_URL="https://freeinference.org/v1" and MODEL="qwen3.6-35b". Add FREEINFERENCE_API_KEY to Colab Secrets, or enter it privately when prompted. Change BASE_URL, MODEL, and SECRET_NAME to use another compatible service.

04 / Observe the result

Make every call count

Read the input, response, validation checks, and trace. Keep the call budget small. Never commit a credential or assume a green assertion proves an architecture recommendation is correct.

One interface, configurable providers: the live adapter expects an OpenAI-compatible Chat Completions API. FreeInference is the initial configuration; a university gateway or another compatible service can use the same adapter. Check current model access, quota, and API compatibility before class. The initial Qwen model is enough for the introductory calls; live council labs require three distinct model families configured separately.

Where this leads

A council of AI architects.

The labs prepare you for the course project: architects that propose independently, challenge one another, and present a traceable recommendation to a human.

Software architecture project

Think alone.
Debate together.
Keep the evidence.

Give every architect the same requirements and knowledge base. Use different model families and explicit stances. Record proposals, critiques, revisions, the chair’s decision, and any minority view.

Connect the labs to the project ↗
Diversity

Three agents are not automatically three perspectives.

The project calls for at least three different model families. Changing a system prompt or temperature on one model is useful practice; it does not meet that requirement.

Control

A debate needs an ending.

Bound the rounds and tool calls. Specify a deadlock rule. Record dissent and escalate unresolved decisions. The human architect retains the final decision.

Evidence

Measure whether it helped.

Compare with each constituent model used alone under the same scenario and evidence. Learn only from the feedback set, then evaluate on held-out scenarios. Report cost and latency alongside decision quality.

These are learning exercises, not a finished project submission. The toy examples do not establish that a council outperforms a single model. Your project needs its own design, expert-reviewed benchmark, and evaluation.

Yao et al. study reasoning and acting. Our tool lab focuses on explicit actions and observations rather than private model reasoning.
